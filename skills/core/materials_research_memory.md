# Materials Research Memory — usage protocol

This skill wires the `materials-research-memory` plugin into a DSH session.
It is the "session hooks" implementation (DSH has no native hook API; see
DSH_PLUGIN_CAPABILITY_AUDIT.md). Follow it at the three session boundaries.

Plugin root: `~/.dsh/plugins/materials-research-memory`
CLI: `python <plugin_root>/bin/materials-memory.py --root <plugin_root> <verb>`

## When to use

- At every session start / when a session is about to work on a research
  project.
- Before starting any research task (retrieve relevant memory).
- After finishing any research task (reflect and propose memory updates).

## Session start (spec §12)

1. Run: `materials-memory brief`
   → regenerates `outputs/PROJECT_BRIEF.md` (≤ 8000 tokens) from
   PROJECT_MEMORY + SCIENTIFIC_STATE (current stage, canonical definitions,
   latest conclusions, blockers, next steps).
2. Read `outputs/PROJECT_BRIEF.md` before doing research work.
   Do NOT paste all memory into context — only the brief.

## Task start (spec §13)

Before executing a task, run:
`materials-memory retrieve "<task query>" -k 5`
Use the top-k memories (project memory, scientific state, decisions,
lessons, skills, data registry) as TASK_CONTEXT. Never rely on memory that
was not retrieved.

## Task end (spec §15–17)

After a task, answer the nine reflection questions and produce a proposal:

`materials-memory reflect --task-id <id> --summary "<summary>" \
  --answer "<what new fact was established?>" ... \
  --facts '{"topic": "...", "value": "...", "source": "..."}' \
  --lessons '{"trigger":"...","failure":"...","root_cause":"...","fix":"...",\
             "generalizable_rule":"...","scope":"...","source":"...",\
             "confidence":"MEDIUM"}' \
  --canonical-source "<path>"`

Rules:
- Observations, task logs, and CANDIDATE lessons are auto-committed.
- Accepted scientific conclusions are auto-committed ONLY when source is a
  canonical final result AND confidence is HIGH AND no conflict exists.
  Otherwise they are recorded with `requires_review=true` — never accepted
  silently.
- Never overwrite accepted scientific truth. A conflict marks the old claim
  SUPERSEDED and keeps full history (decision_id / lesson_id stay stable).

## Skill promotion (spec §19)

Run `materials-memory propose-skills` to list lessons eligible for
promotion (VERIFIED + times_verified≥2 + HIGH + generalizable). Write the
real skill only after human/reviewer approval via `promote-skill`.

## Claim gate (spec §20)

Before outputting a scientific conclusion, apply the `scientific_claim_gate`
skill (sample size, matched design, data coverage, convergence, outlier
sensitivity, topology sensitivity, confounding, cross-validation,
provenance, method consistency). If any check fails, lower the claim
strength.

## Outputs

- `outputs/PROJECT_BRIEF.md` — session-start brief.
- `outputs/TASK_CONTEXT.md` — task retrieval context (generated by agent
  from `retrieve` results).
- `reflections/task/*.md` — MEMORY_UPDATE_PROPOSAL per task.
- `outputs/SKILL_PROMOTION_PROPOSAL.md` — promotion candidates.

## Common failures

- Pasting the whole memory into context (blows the budget; use the brief).
- Auto-accepting a non-canonical conclusion (gated — requires_review).
- Overwriting an accepted claim (contradiction detection supersedes instead).
- Trusting filenames over the DATA_REGISTRY status field for dataset
  freshness.

## Blocking conditions

- Memory not initialized: run `materials-memory init` first.
- Python < 3.10 or PyYAML missing: install before use.
